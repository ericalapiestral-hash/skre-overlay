# SKRE 오버레이

세븐나이츠 리버스 **파괴신·공성전** 전용 빌드 오버레이. 게임 화면 위에 스킬 순서를
띄워 두고, 게임의 턴 숫자를 읽어 다음 단계로 자동으로 넘겨준다.

길드봇([guild-bot](https://github.com/ericalapiestral-hash/guild-bot))이 노션 도감을
읽어 만들어 두는 `data/builds.json`을 그대로 읽는다 — 노션 토큰도, 네트워크도 필요 없다.

## 쓰는 법

```
npm install
npm start
```

1. 게임을 **테두리 없는 창모드**로 켠다 (전용 전체화면에서는 오버레이가 안 보인다).
2. **[턴 영역]** 을 눌러 게임 화면에서 턴 숫자만 드래그로 감싼다.
3. **[자동]** 을 켠다. 이제 턴이 바뀔 때마다 다음 단계로 넘어간다.

빌드는 위쪽에서 고른다. 공성전 탭은 **오늘 요일 보스**를 먼저 골라 준다.

### 단축키 (게임에 포커스가 있어도 동작한다)

| 키 | 하는 일 |
|---|---|
| `Ctrl+Alt+O` | 숨기기 / 보이기 |
| `Ctrl+Alt+L` | 클릭 통과 (오버레이가 게임 조작을 방해하지 않게) |
| `Ctrl+Alt+R` | 턴 영역 다시 지정 |
| `Ctrl+Alt+←` `→` | 단계 앞뒤로 이동 |
| `Ctrl+Alt+Space` | 자동 켜기 / 끄기 |

손으로 단계를 옮겨도 **자동은 꺼지지 않는다** — 옮긴 자리에서 계속 따라간다.

### 연출·밀림에도 따라간다

- 스킬 연출로 턴 숫자가 **가려지는 동안**은 단계를 그대로 두고, 돌아오면 바로 따라잡는다.
- 연출이 숫자를 **반쯤 가려** 엉뚱하게 읽혀도(16이 6으로) 단계가 튀지 않는다.
- 게임 효과로 턴이 **한두 턴 뒤로 밀려도** 이미 한 단계를 다시 보여주지 않는다.
- **재시작**은 0이 한참(0.6초 넘게) 가만히 있어야 믿는다. 잘못 믿었으면 곧 되돌린다.
- 라운드마다 턴이 0부터 다시 시작하는 빌드도 안다. 보스가 곧 죽을 걸 알고 **다음 라운드를
  손으로 미리 골라 둬도** 그 라운드를 건너뛰지 않는다.

상태줄에 추적기가 지금 왜 안 움직이는지가 나온다 ("재시작인지 확인 중", "턴이 뒤로 밀림 — 단계 유지").

### 잘 안 읽힐 때

**[가르치기]** 를 누르면 지금 잡히는 화면과 함께 "실제 턴 숫자"를 넣는 칸이 나온다.
한 번 넣어 주면 그 화면에서 뽑은 숫자 모양이 대조표에 들어가, 그 뒤로는 훨씬 잘 읽는다.
기본 대조표는 흔한 폰트로 만든 것이라 게임 폰트와 조금씩 다르다.

그 밖에 확인할 것:

- 턴 영역이 **숫자에만** 딱 맞는지 (아이콘·다른 글자가 같이 들어오면 헷갈려 한다)
- 오버레이 창이 턴 숫자를 가리고 있지 않은지
- 게임이 테두리 없는 창모드인지

### 도감을 못 찾을 때

앱은 이 자리들을 차례로 본다.

```
(exe 옆) data/builds.json  ·  (exe 옆) builds.json
바탕화면/길드봇/data/builds.json
바탕화면/guild-bot/data/builds.json
```

못 찾으면 **[⚙] → [도감 파일 선택]** 으로 직접 고르면 된다. 고른 경로는 기억한다.
길드봇이 도감을 새로 받아오면 오버레이도 **자동으로 다시 읽는다** (전투 중이면
보던 빌드와 진행 위치는 그대로 둔다).

스킬 순서를 자동으로 못 읽은 빌드는 목록에 `⚠` 표시로 남고, 도감 본문을 그대로 보여준다.
**목록에서 빼지 않는다** — 도감엔 있는데 오버레이엔 없는 상황이 제일 답답하기 때문이다.

## 개발

```
npm test         파서 · 추적 · 인식기 · 도감 읽기 + 전투 시나리오 82개 (167개)
npm run typecheck 타입 검사 (JSDoc 기반, 빌드 단계 없음)
npm run check    위 둘 다
npm run doctor   도감을 어디서 찾았고 몇 개를 읽었는지 (화면 없이)
npm run bench    숫자 인식기 정확도·속도 재기
```

`npm run bench`는 진짜 폰트로 그린 표본 792장을, **앱이 실제로 넣는 것과 같은 조건**
(크롭을 64px로 키우고 빌드 턴을 후보로 넘김)으로 읽어 맞음·모르겠음·틀림과 걸린
시간을 보여준다. 지금은 **792장 전부 맞음, 한 장에 0.66ms**다.

`npm run doctor` 는 게임을 켜지 않고도 "도감이 제대로 읽히는지"를 확인한다.
빌드가 안 보인다는 얘기가 나오면 여기부터 보면 된다.

### 구조

```
src/
  main/       메인 프로세스 — 창 · 단축키 · 도감 · 인식 엔진
    index.js    앱 시작, 창, IPC, 전역 단축키
    catalog.js  builds.json 찾기 · 읽기 · 감시
    engine.js   픽셀 한 장 → "지금 몇 번째 단계인지"
    config.js   설정 저장 (원자적 쓰기)
  shared/     화면도 캡처도 모르는 순수 로직 (전부 테스트로 확인된다)
    steps.js      도감 본문 → 스킬 순서 단계
    turnReader.js 숫자 인식기 (의존성 없음)
    follower.js   턴 추적기 — 연출·밀림·재시작을 견디며 단계를 따라간다
    tracker.js    라운드 나누기 도우미
    templates.json 숫자 대조표
  preload/    화면에 열어 주는 통로 (contextIsolation)
  renderer/   화면 — 고르고, 그리고, 캡처만 한다
tools/        대조표 만들기 · 표본 만들기 · 성능 재기 · 문턱값 재기
test/         단위 테스트 + 전투 시나리오(scenarios/*.json)
```

**판단은 전부 메인에 있다.** 화면에는 캡처와 그리기만 남겼다. 그래야 인식·투표·단계
이동을 Node 테스트로 전부 확인할 수 있다 — 예전에는 이 로직이 렌더러 안에 섞여 있어서
게임을 직접 돌려보는 것 말고는 확인할 방법이 없었다.

### 배포용 exe

```
npm run dist    → dist/skre-overlay-1.0.0.exe (포터블, 설치 불필요)
```

> ⚠️ **exe를 공개된 곳에 올리지 말 것.** 도감(`builds.json`)이 길드 내부 자료다.
> exe 자체에는 도감이 안 들어가지만, exe 옆에 `data/builds.json`을 두고 배포하면
> 그게 같이 나간다. 길드 안에서만 돌린다.
