# 전투 시나리오 — 턴 추적기가 지켜야 하는 것

턴 추적기(`src/shared/follower.js`)는 "프레임마다 읽힌 턴 숫자(또는 가려짐)"를 받아
"지금 할 단계(index)"를 정한다. 여기 JSON 파일들은 실제 전투에서 벌어지는 일을
프레임 단위로 적어 둔 것이고, `test/scenario.test.js`가 전부 돌려 본다.

## 게임에서 실제로 벌어지는 일

- **스킬을 쓰면 연출 때문에 턴 숫자가 가려진다.** 0.3~3초. 그동안은 아무것도 못 읽는다(null).
  가려지는 동안에도 전투는 진행되어, 돌아왔을 때 턴이 여러 개 지나 있을 수 있다.
- **연출이 숫자를 반쯤 가리면 엉뚱하게 읽힌다.** "16"의 1이 가려져 "6"으로, "8"의 가운데가
  가려져 "0"으로. 한 프레임에서 몇 프레임까지 이어질 수 있다.
- **턴이 한두 턴 뒤로 밀린다.** 게임 효과로 표시 턴이 1~2(드물게 3) 줄어든다. 이건
  오독이 아니라 실제다. 다시 올라간다.
- **전투를 다시 시작하면** 턴이 처음(0 또는 1)으로 돌아간다. 보통 몇 초 가려진 뒤에.
- **빌드는 두 종류다.**
  - 이어지는 빌드: 턴이 문서 전체에서 이어진다 (1라운드 0·4·8 → 2라운드 12·16 → …)
  - 리셋 빌드: 라운드마다 0부터 다시 시작한다 (1라운드 0·4 → 2라운드 0·4 → 3라운드 0)
    라운드가 넘어갈 때는 연출(가려짐) 뒤에 작은 숫자가 나온다. 보스가 일찍 죽으면
    단계를 다 못 한 채로 다음 라운드가 시작될 수 있다. 한 라운드가 마지막 단계의
    턴보다 한참 더 갈 수도 있다 (4턴 단계가 끝인데 12턴까지 감).
- 프레임 간격은 **100ms**로 가정한다.

## 추적기가 지켜야 하는 정책

- **P1 앞으로**: 받아들인 턴 t가 지금 단계의 턴 이상이면, 지금 위치부터 앞으로 훑어
  "턴 ≥ t"인 첫 단계로 간다. 이어지는 빌드는 다음 라운드로도 넘어간다. 리셋 빌드는
  **현재 라운드 안에서만** 찾고, 없으면 라운드 마지막 단계에 머문다 (라운드가 아직 안 끝났다).
- **P2 가려짐**: null 프레임은 절대 단계를 움직이지 않는다.
- **P3 작은 뒤로(1~3턴)**: 단계를 **그대로 둔다**. 이미 한 단계를 다시 보여주면 안 된다.
- **P4 큰 뒤로**: 그대로 둔다 — 확인된 재시작(P6)이나 리셋 라운드 전환(P5)만 예외.
- **P5 리셋 라운드 전환**: 리셋 빌드에서, 다음 라운드 첫 턴 이하의 숫자가 **2프레임 이상**
  이어지면 다음 라운드 첫 단계로. 현재 라운드 마지막 단계에 있을 때는 그것으로 충분하고,
  라운드 중간이면 그 앞에 **500ms 이상 가려짐**이 있어야 한다 (보스가 일찍 죽은 경우).
- **P6 재시작**: 빌드 첫 턴 이하(+1 여유)의 숫자가 **600ms 이상(7프레임)** 가려짐 없이
  이어지면 처음으로. 리셋 빌드에서는 마지막 라운드에서만 (그 전엔 P5가 먼저다).
  진짜 재시작은 0이 몇 초씩 가만히 있으니 오래 기다려도 손해가 없다.
- **P7 수상한 앞으로**: 지금 단계에서 **두 단계 이상** 건너뛰는 이동은 **3프레임** 이어져야
  한다. 오독("16"→"46")으로 순간이동하지 않게.
- **P8 되돌리기**: P7로 크게 건너뛰거나 P6으로 재시작한 뒤 **3초 안에** 그 전 위치에 맞는 숫자
  (그 전 턴 −3 ~ +6)가 3프레임 이어지면, 그 전 위치로 돌아가 거기서부터 다시 따라간다.
  ("1"로 잘못 읽혀 재시작했는데 17·18이 돌아오는 경우)
- **P9 손으로 옮김**: 사용자가 단계를 옮기면 거기가 기준이 된다. 그 뒤 읽기는 평소처럼.
- 또렷한 읽기(plain 숫자)는 **1프레임**에 받아들인다. 흐린 읽기(`{"v":n,"weak":true}`)는
  2프레임 같아야 받아들인다.
- P5~P8의 "이어진다"는 **같은 값**이 아니라 **같은 조건**(건너뛸 곳이 같은 단계다 /
  첫 턴 근처다 / 다음 라운드 첫 턴 이하다 / 뛰기 전 위치 근처다)이 이어지는 것이다.
  전투 중엔 턴이 프레임마다 바뀌므로 같은 값을 기다리면 영영 못 넘어간다.
  **가려짐(null)은 이어짐을 끊는다** — 진짜 재시작·전환은 가만히 있고, 연출 중 오독은 깜빡인다.
- 지금 단계의 턴을 지나면 곧바로 다음 단계가 "지금"이 된다: 4턴 단계를 보다 턴이 5가 되면
  다음 단계(8턴)가 지금 할 행동이다. expect를 적을 때 여기서 자주 틀린다.

## 파일 형식

```json
{
  "name": "연출 중 부분 가림 — 16이 6으로",
  "why": "스킬 연출이 1을 가려 6으로 읽힌다. 뒤로 가는 값이므로 단계는 그대로여야 한다.",
  "build": "running",
  "steps": [ { "turn": 0, "label": "1라운드" }, { "turn": 4, "label": "1라운드" } ],
  "start": 0,
  "frames": [ 0, 0, 1, 2, null, null, 6, 6, 6, null, 17, 18 ],
  "expect": [
    { "by": 2, "index": 1 },
    { "from": 6, "to": 9, "hold": 1 },
    { "at": 11, "index": 1 }
  ]
}
```

- `build`: `"running"` | `"reset"` (문서용 표시. 추적기는 steps에서 스스로 알아낸다)
- `steps`: 펼쳐진 단계. 같은 `label`이 이어지는 구간이 한 라운드.
- `start`: 시작 index (없으면 0)
- `frames`: 프레임마다 읽힌 값. 숫자 = 또렷한 읽기, `null` = 가려짐,
  `{"v": 16, "weak": true}` = 흐린 읽기, `{"set": 3}` = 사용자가 이 프레임에 단계 3으로 손으로 옮김 (P9, 읽기 없음)
- `expect`: 확인 항목. 프레임 번호는 0부터.
  - `{ "by": k, "index": n }` — k번째 프레임까지는(포함) index가 n이어야 한다
  - `{ "at": k, "index": n }` — 정확히 k번째 프레임 뒤에 index가 n
  - `{ "from": a, "to": b, "hold": n }` — a~b 프레임 내내 n
  - `{ "from": a, "to": b, "min": n }` — a~b 프레임에서 n 아래로 안 내려간다
  - `{ "from": a, "to": b, "max": n }` — a~b 프레임에서 n을 안 넘는다
